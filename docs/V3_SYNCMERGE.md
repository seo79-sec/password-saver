# PasswordSaver 3.0. Ядро слияния в памяти

`internal/syncmerge` принимает синтетические операции над записями. Контракт
этого этапа внутренний. Сетевой конверт, долговечность очереди и проверка
полномочий автора описаны как следующие стадии в [архитектуре](V3_ARCHITECTURE.md).

## Контракт API

Создайте реплику через `New(maxPending)`. Каждый вызов `Apply(Operation)`
подаёт одну полную версию записи. Операция содержит непустые `ID`,
`AuthorID`, `RecordID`, список `Parents`, действие `Put` либо `Delete` и
байты `Data`. Удаление имеет пустые данные. Запись определяется только
`RecordID`. Автор и содержимое участвуют в проверке повтора, метки времени
для выбора версии отсутствуют.

Родители — уникальные ID версий той же записи. Без родителей операция
создаёт независимый корень. Порядок родителей не влияет на равенство
операций. Пустой срез и `nil` эквивалентны. Точный повтор уже принятой
операции возвращает `Applied`, а повтор ожидающей — `Waiting`. Один ID с
другим автором, записью, действием, предками или байтами отклоняется.
Реплика сохраняет первое принятое или находящееся в очереди определение.

| Итог | Значение |
| --- | --- |
| `Applied` | Операция присутствует в принятой истории. |
| `Waiting` | Не все родители приняты. Видимые версии пока сохраняются. |
| `Rejected` | Операция отклонена с причиной в `Err`. Уже принятые данные сохраняются. |

`Result.Resolved` перечисляет операции из очереди, которые при приёме
зависимости были применены или отклонены. Например, после получения
родителя другой записи ожидающая операция отклоняется с
`ErrParentRecord`, а корректный родитель принимается. Отвергнутое
определение освобождает место. Операции, ссылавшиеся на его ID, ждут
допустимое определение. Реплика отклоняет самоссылки, повторы в списке
родителей и операции, замыкающие цикл в очереди. Недопустимые определения
ID не резервируются.

Лимит ограничивает число ожидающих операций. При заполненной очереди
операция с отсутствующим родителем получает `ErrPendingLimit` и может быть
подана повторно. Готовые операции и точные повторы по-прежнему принимаются.
Нулевой лимит разрешает подачу операций с уже принятыми зависимостями.
Вызывающий код отвечает за переотправку после переполнения, сроки выдачи
недостающих операций, ограничения объёма данных и остановку бесконечной
потери сообщений.

## Состояние и конфликты

`Snapshot()` возвращает максимальные версии каждой записи в порядке ID
записи и операции. Предок последующей версии остаётся в истории. Правки
в разных записях независимы. Одновременные правки и действие удаления
сохраняются целыми версиями. Разрешение — обычная операция, которая
указывает все версии, вошедшие в решение. Поздняя версия за пределами
этих предков остаётся конфликтующей. Единственная версия удаления
остаётся в снимке и истории.

`History()` возвращает все принятые версии в порядке ID для сравнения.
Для воспроизведения используйте порядок зависимостей либо очередь и
повтор при исчерпании лимита. Реплика копирует входные срезы и возвращает
независимые копии записей и истории. Вызовы одной реплики сериализует
владелец. История и версии удаления хранятся до уничтожения реплики.

При одном и том же полностью доставленном допустимом наборе результат
одинаков. Допустимый набор замкнут по родителям, ацикличен и содержит
одно определение на ID. При наличии противоречивых определений результат
их индивидуального отклонения зависит от того, какое определение
поступило первым. Источники и подписи проверит следующий слой.

## Пример двух реплик

```go
first, second := syncmerge.New(2), syncmerge.New(2)
base := syncmerge.Operation{ID: "base", AuthorID: "a", RecordID: "r", Action: syncmerge.Put}
edit := syncmerge.Operation{ID: "edit", AuthorID: "a", RecordID: "r", Parents: []string{"base"}, Action: syncmerge.Put, Data: []byte("new")}
deleted := syncmerge.Operation{ID: "delete", AuthorID: "b", RecordID: "r", Parents: []string{"base"}, Action: syncmerge.Delete}

first.Apply(base)
first.Apply(edit)
first.Apply(deleted)

second.Apply(deleted) // Waiting
second.Apply(base)    // Applied, resolves "delete"
second.Apply(edit)
// Both snapshots have the full "delete" and "edit" variants of record "r".
```

Тест сходимости доставляет семь допустимых операций во всех 5 040 порядках,
вставляет повторы и сравнивает содержимое снимка и истории. Отдельные
тесты проверяют повреждённые зависимости, поздний конфликт, ёмкость очереди
и владение срезами. [Тесты и исполняемый пример](../internal/syncmerge/merge_test.go)
