# PR #12: ручная проверка Windows EXE

Статус: сценарий подготовлен; запуск GUI в облачной Linux-среде не выполнен.
Успешные Go tests и Windows Wails build не доказывают работу нативного диалога,
WebView2 и всех политик доступа на пользовательских Windows.

## Изолированный стенд

Использовать отдельную Windows VM/тестовую учётную запись с WebView2, пустым
тестовым AppData и синтетическими данными. Не переименовывать, не удалять и не
перезаписывать каталог PasswordSaver основного пользователя. Для каждого
сценария возвращать снимок тестовой VM либо использовать новый тестовый профиль.

- Сборка PR #12 из проверяемого commit (зафиксировать SHA и SHA-256 EXE).
- Неизменённый EXE релиза 2.0.0 для воспроизведения старых способов запуска.
- Отдельные папки `C:\PS-Test\Application`, `C:\PS-Test\WorkingVault` и,
  если доступен отдельный тестовый диск, `D:\PS-Test\Vault`.
- Синтетический мастер-пароль, несколько вымышленных записей и тестовый TOTP.
- Исходный v1 fixture — только с синтетическими данными. Для v2 создать набор
  через 2.0.0, добавив минимум две записи, чтобы появилась `.bak`.

Перед переносом записать SHA-256 **всех** файлов источника через `Get-FileHash`,
включая EXE, checksum и произвольный `notes.txt`. Записать их ACL через `icacls`.
После каждой отмены/ошибки и успешного переноса сравнить байты и ACL источника.
Проверять только тестовый `%LOCALAPPDATA%\PasswordSaver\vaults\default`.

| Legacy рядом с EXE | Поместить синтетический v1/v2 набор рядом с EXE и checksum | Обнаружен перенос; до подтверждения вход/создание заблокированы; EXE и посторонние файлы не копируются |
| Другой CWD | Запустить 2.0.0 через `Start-Process -FilePath C:\PS-Test\Application\password-saver.exe -WorkingDirectory C:\PS-Test\WorkingVault`; создать синтетический vault, закрыть 2.0.0 | Старые файлы находятся в WorkingVault |
| Ярлык Start in | Указать WorkingVault в поле «Рабочая папка» ярлыка PR EXE | CWD автоматически не выбирается; «Указать расположение вручную» позволяет выбрать WorkingVault |

| Авторизация | Ввести неправильный пароль, затем правильный пароль и неправильный TOTP | Нет копирования; после пяти неверных TOTP действует существующая блокировка, повторный выбор/Logout её не снимают |
| Отдельное подтверждение | Проверить правильный пароль/TOTP, закрыть окно до подтверждения; повторить и подтвердить | При отмене target пуст/отсутствует; после подтверждения каждый известный файл равен источнику побайтово |
| Истечение/перезапуск | Ждать более двух минут на выборе/подтверждении; закрыть/перезапустить EXE до подтверждения | Старые токены не действуют; выбрать папку и аутентифицироваться можно снова |
| Запоздалый ответ | Закрыть чувствительное окно/заблокировать приложение во время проверки; повторить при медленном источнике | Старый ответ не открывает окно заново, не возвращает пароль/TOTP/токен |
| Защита от второго пустого vault | Во время выбора/подготовки вызвать создание нового | UI и backend запрещают создание; новый vault доступен только после отмены выбора и осознанного подтверждения |
| Конфликт | Существующий AppData + выбранный legacy; два legacy в EXE и выбранной папке | Копирование не начинается; оба набора сохранены, даже если выбранные файлы совпадают с AppData |
| Изменение после подготовки | В тестовой VM изменить source backup или создать файл в target между этапами | Подтверждение отклонено; никаких перезаписей |
| Повреждённый primary | Повредить только синтетический primary при правильной backup | Перенос проверяет backup, сохраняет оба файла без изменения; recovery после переноса требует отдельного подтверждения и создаёт диагностический архив |
| Неподдерживаемый формат | Изменить version/algorithm в тестовом v2 primary | Нет автоматического отката к backup/v1 и обхода селектора |
| CRUD/TOTP | После переноса войти, пройти TOTP, добавить/изменить/удалить вымышленные записи, перезапустить EXE | Изменения и backup только в AppData; исходный набор неизменен |
| Восстановление v1/v2 | После переноса повредить тестовый AppData primary и выполнить явное recovery | Существующая логика recovery, TOTP и диагностического архива работает; selector не откатывается автоматически |
| Смена CWD/папки EXE | Переместить только тестовый PR EXE, запустить из другой папки | Продолжает использовать то же AppData |
| Symlink/junction | Подставить junction вместо source/target либо известного vault-файла | Отказ без записи; посторонний файл внутри managed root также блокирует операцию |
| ACL | Проверить `PasswordSaver`, `vaults`, `default`, `backups`, `config`, vault/backup/selector/receipt через `icacls` | Только текущий пользователь, SYSTEM и Administrators; у файлов корректный DACL; `%LOCALAPPDATA%` и source ACL не изменены |
| Отказ диска | На изолированном стенде запретить запись target, заполнить тестовый диск, удержать destination внешним процессом | Ошибка не удаляет source и не перезаписывает существующий target |
| Сбой процесса | Завершить тестовый EXE во время staging; снова запустить | Незавершённый staging не активируется и не удаляет source; успешную опубликованную копию можно распознать по квитанции |

## Что приложить к повторному security review

- Версия Windows, тип ФС, версия WebView2, SHA commit и хеш EXE.
- Результат каждого сценария; отдельно отметить реальные второй диск, shortcut,
  Controlled Folder Access/корпоративный профиль, если они проверялись.
- Сравнение исходных SHA-256/ACL и ожидаемых target-файлов, без паролей и TOTP-секретов.
- Наблюдения при отказах и повторном запуске. Не заявлять гарантированную
  устойчивость к потере питания: на Windows используются существующие
  file-sync + `MoveFileEx(...WRITE_THROUGH)`, без переносимой гарантии fsync каталога.

Тестовая буква диска в Windows CI проверяет абсолютные пути и копирование между
разными drive letters. Она не заменяет ручную проверку отдельного физического
диска, съёмного носителя или сетевой файловой системы.
