## 2B, PR 1/3 — ключ локальной реплики

- Случайный ключ реплики оборачивается через HKDF-SHA256 от DEK и AES-256-GCM с привязкой к ID и версии обёртки.
- Go-операции требуют полной разблокировки v2, включая TOTP при его наличии.
- Тесты с `-race` прошли. Смена известного пароля сохраняет доступ, ротация DEK делает старую обёртку недействительной.

## 2B, PR 2/3 — пробный перенос и экспорт

- Пробный перенос сверяет записи после повторного открытия SQLite и возвращает ID кандидата и SHA-256 исходного v2.
- Экспорт проверяет повторную разблокировку перед созданием файла v2 с локальным TOTP и существующим recovery-слотом.
- Тесты с `-race` прошли для обеих ревизий v2, дубликатов ID, конфликта версий и повторной попытки после ошибки записи.

## 2B, PR 3/3 — активация и откат на копии

## 3, PR 1/3 — CBOR-кодек конверта изменения

- `internal/syncwire` кодирует конверт изменения v1 как детерминированный CBOR-массив `[H, C, S]`. Разбор проверяет лимит 65 792 байта до декодирования, форму, поля и каноничность.
- Фиксированный hex-вектор, round-trip и тесты отказов прошли с `go test -race ./internal/syncwire`.

## 3, PR 2/3 — шифрование и подпись конверта

- `Seal` шифрует нагрузку AES-256-GCM с ключом из HKDF-SHA256 и подписывает заголовок и шифротекст Ed25519. `Open` проверяет пространство, эпоху и подпись доверенного устройства до расшифровки.
- `go test -race ./internal/syncwire` прошёл с независимым вектором, граничными размерами и тестами подмены, включая повторно подписанный заголовок.

## 3, PR 3/3 — приём изменений на реплике в памяти

- Приёмник проверяет конверт, декодирует нагрузку и передаёт изменение в `syncmerge` после проверки цепочки писателя и родителей записи.
- `go test -race ./internal/syncwire ./internal/syncmerge` прошёл. Две тестовые реплики сохранили обе параллельные правки, обработали повтор и отклонили развилку.

## 3, подключение, PR 1/6 — подписанный запрос устройства

- `go test -race ./internal/syncpair` прошёл с фиксированным вектором и проверками срока действия, подмены ключей, подписи, каноничности и лимита 512 байт.

- `go test -race ./internal/syncpair` прошёл с проверками подтверждённого отпечатка, подписи, связи составов, неизменности владельца и уникальности ID и ключей.

## 3, подключение, PR 4/6 — перенос истории в начальном снимке

- `go test -race ./internal/syncwire ./internal/syncmerge` прошёл с восстановлением конфликта и удаления, отклонением повреждённого снимка и приёмом первого изменения новой эпохи.

## 4, PR 1 — журнал локального тестового реле

- Журнал одного пространства хранит непрозрачные конверты в памяти и выдаёт их по курсору страницами до 64 записей. Точный повтор возвращает прежний курсор даже при заполненной квоте.
- `go test -race ./internal/syncrelay` прошёл с проверками пагинации, отказа по квоте, параллельной отправки и защиты сохранённых байтов.

## 4, PR 2 — HTTPS-обработчик тестового реле

- `POST` и `GET /v1/envelopes` работают по TLS с Bearer-токеном. Обработчик сверяет SHA-256 токена, ограничивает размер записи и выдаёт страницы с курсором `next`.
- `go test -race ./internal/syncrelay` прошёл с повторной отправкой, пагинацией и проверкой, что отклонённые запросы оставляют журнал без изменений.

## 4, PR 3 — HTTPS-клиент тестового реле

- `Push` и `Pull` используют TLS с проверкой сертификата и Bearer-токен. Клиент ограничивает ответ до разбора JSON, проверяет курсоры и возвращает отдельную ошибку при `507`.
- `go test -race ./internal/syncrelay` прошёл с проверками двух страниц, недоверенного сертификата, неверного `next`, слишком большого ответа и запрета редиректа.

## 4, PR 4 — подписанный конверт локальной правки

- `SealOperation` проверяет локальную операцию, использует переданные номер и хеш предшественника и возвращает подписанные байты конверта с их SHA-256.
- `go test -race ./internal/syncwire` прошёл. `Receiver` принял правку и удаление с родителем, а `SealOperation` отклонил дубли, превышение лимита родителей и данные в удалении.

## 4, PR 5 — восстановление реплики из снимка и журнала

- `Replay` восстанавливает подтверждённый снимок и повторно подаёт ожидающие конверты после принятия изменений. Лимит ожидания составляет 64 конверта и 256 КиБ.
- `go test -race ./internal/syncwire` прошёл с доставкой потомка раньше родителя, повторным открытием и отказами при развилке и превышении квоты.

## 4, PR 6 — журнал и прогресс обмена в SQLite-реплике

- Журнал до 4 096 конвертов и 4 МиБ, метаданные локальных команд и курсоры сохраняются вместе в зашифрованном BLOB с проверкой поколения. Снимок восстанавливается из подтверждённого checkpoint и журнала.
- `go test -race ./internal/replicastore -run 'TestExchange'` прошёл с чтением старой реплики, повторным открытием секции и проверками устаревшего поколения и сбоя перед commit.

## 4, PR 7 — атомарная постановка локальной правки в очередь

- `QueueLocal` фиксирует правку, подписанные байты и ID команды одной транзакцией. Точный повтор возвращает сохранённый конверт, а после неопределённого commit результат сверяется по ID.
- `go test -race ./internal/syncsession -run '^TestQueueLocal'` прошёл с офлайн-правкой, повторным открытием и сбоем сразу после commit.

## 4, PR 8 — атомарный приём страницы конвертов

- `AcceptPage` сохраняет новые конверты и курсор чтения одним commit. Точные повторы и собственное эхо продвигают курсор без второй записи в журнале.
- `go test -race ./internal/syncsession -run '^TestAcceptPage'` прошёл. Ожидание переживает повторное открытие, а неверная подпись, развилка и превышение квоты оставляют поколение и курсор прежними.

## 4, PR 9 — явный запуск обмена

- `RunOnce` отправляет старейший неподтверждённый конверт и читает одну страницу. После потери ответа повторяются те же байты, а при 507 очередь сохраняется и приём продолжается.
- `go test -race ./internal/syncsession` прошёл. Без включения обмена и полной разблокировки запросов нет. Блокировка отменяет запрос, а поздний ответ не меняет прогресс.
