# PasswordSaver 3.0–2A. Локальная реплика

`internal/replicastore` хранит одну реплику `internal/syncmerge` в SQLite.
Пакет пока используется только в тестовых каталогах. Рабочий CRUD, Wails,
хранилища v1/v2 и выбор активного формата работают через прежние пути.
[Контракт слияния](V3_SYNCMERGE.md) · [Модель угроз](V3_THREAT_MODEL.md)

## Внутренний API

| Метод | Контракт |
| --- | --- |
| `Create(ctx, path, key)` | Создаёт пустую реплику в существующем локальном частном каталоге. Резервирует путь эксклюзивно. При неудачной инициализации оставляет файл для диагностики. |
| `Open(ctx, path, key)` | Проверяет существующую БД, схему, AEAD и возможность воспроизвести состояние. Отсутствующий файл остаётся отсутствующим. Неверный ключ и нарушение тега дают общий `ErrAuthentication`. Неизвестная схема даёт `ErrSchema`, структурные ошибки распознаются как повреждение либо возвращаются из SQLite. |
| `Apply(ctx, op, source)` | Применяет входящую или локальную операцию. Возвращает `syncmerge.Result` после commit изменения. При неизменившемся повторе или отклонении сообщает статус без записи. Вызывающий код обрабатывает и ошибку хранения, и статус/ошибку ядра слияния. |
| `Read(ctx)` | Возвращает независимый снимок последнего зафиксированного поколения. Содержит варианты записей, всю принятую историю, ожидающие операции, счётчик и outbox. |
| `Close()` | Закрывает соединение и затирает копию ключа в объекте. Открытие с тем же путём и ключом восстанавливает состояние. Затирание других копий в памяти Go не гарантируется. |

Вызывающий код генерирует отдельный случайный 256-битный ключ, хранит его в
памяти на время доступа и передаёт как `[32]byte`. Интеграция обёртки ключа с
локальной разблокировкой относится к 2B. Каждая локальная операция получает
порядковый номер при принятии. Локальная операция, которая ждёт родителей,
получает номер после их появления. Первая доставка ID задаёт источник
операции. Точный повтор с любым источником возвращает прежний статус,
сохраняет номер и не добавляет строку в outbox. Входящие операции не получают
локальный номер. Конфликты и tombstone сохраняются по правилам `syncmerge`.

## Схема 1 и шифрование

`PRAGMA application_id = 0x50535253` и `PRAGMA user_version = 1` маркируют
схему. Чтение проверяет объявление таблицы и отклоняет посторонние объекты
схемы. Единственная строка содержит случайный 16-байтовый ID реплики, целое
поколение от 1 и зашифрованный BLOB. Внутри BLOB находится JSON со всей
историей в порядке принятия, ожидающими операциями и их источниками,
счётчиком и упорядоченными ссылками outbox на принятую историю. Индекс
вариантов воссоздаётся в памяти. Проверка при открытии воспроизводит историю и
ожидание, проверяет ссылки outbox и соответствие счётчика.

Для каждого сохранения генерируется новая случайная 32-байтовая соль
HKDF-SHA256. Purpose string HKDF равен
`PasswordSaver/replicastore/state/key/v1`. Стандартное Go AES-256-GCM
`NewGCMWithRandomNonce` добавляет случайный 12-байтовый nonce и 16-байтовый
тег. BLOB хранит соль, nonce и шифротекст с тегом. AAD — ASCII-строка
`PasswordSaver/replicastore/state` с одним завершающим нулевым байтом,
16 байт ID реплики, 4 байта версии и 8 байт поколения. Целые кодируются
big-endian. Длина BLOB ограничивается в SQL до передачи в Go. Повтор после
сбоя генерирует новую соль даже при повторном использовании номера поколения.
[Go AES-GCM](https://pkg.go.dev/crypto/cipher#NewGCMWithRandomNonce) ·
[HKDF](https://www.rfc-editor.org/rfc/rfc5869)

SQL получает только шифротекст и открытые технические поля. ID операций,
содержимое записей, счётчик и outbox сериализуются и шифруются в Go до
передачи драйверу. Локальный наблюдатель может видеть ID реплики, поколение,
размеры, структуру SQLite и факты записи. Целостная старая пара файлов
SQLite с тем же ключом может пройти проверку. Обнаружение такого отката
потребует доверенной внешней точки отсчёта. Код предполагает принадлежащий
приложению частный локальный каталог. Отладчики, дампы памяти, подкачка и
подмена каталога процессом с теми же правами выходят за границы защиты.

## SQLite и долговечность

Зафиксирован `github.com/ncruces/go-sqlite3 v0.38.0` (MIT).
Он даёт интерфейс `database/sql`, собирается без CGO с Go 1.26,
использует SQLite, переведённый из Wasm в Go, и собственный Go VFS.
На Windows VFS использует `LockFileEx` и `MapViewOfFile`. На Linux
использует OFD-блокировки и mmap. Остальная сборка Wails использует прежний
драйвер WebView2 и штатный workflow. Зависимость поднимает разрешённые
версии `golang.org/x/crypto`, `x/net`, `x/sys` и `x/text` в общем
Go-модуле. [Драйвер и платформы](https://github.com/ncruces/go-sqlite3/tree/v0.38.0) ·
[Документация VFS](https://github.com/ncruces/go-sqlite3/blob/v0.38.0/vfs/README.md) ·
[Лицензия](https://github.com/ncruces/go-sqlite3/blob/v0.38.0/LICENSE)

БД создаётся в WAL. Каждое соединение использует `synchronous=FULL`,
`busy_timeout=250` мс, `wal_autocheckpoint=256` страниц,
`temp_store=MEMORY` и `trusted_schema=OFF`. Один handle имеет одно
соединение. `BEGIN IMMEDIATE` удерживает право записи до commit. Другой
писатель ждёт или получает `ErrBusy`. Чтение видит зафиксированный снимок.
WAL предполагает локальную файловую систему с общей памятью и рабочими
блокировками. Открытую БД нельзя копировать по одному файлу, поскольку
непрошедшие checkpoint данные могут находиться в WAL.
[SQLite WAL](https://sqlite.org/wal.html) ·
[PRAGMA synchronous](https://sqlite.org/pragma.html#pragma_synchronous) ·
[Транзакции](https://sqlite.org/lang_transaction.html)

Запись выполняется только после чтения текущего снимка в той же транзакции.
Новая история, переходы ожидающих операций, счётчик и outbox фиксируются
одной заменой BLOB. Между вызовами рабочей копии модели в памяти нет.
При ошибке до commit откат оставляет прошлое поколение. При ошибке commit
пакет возвращает `ErrCommitUnknown` без статуса успеха. Вызывающий код читает
состояние или повторяет **ту же операцию с тем же ID и содержимым**. Если
commit состоялся, повтор подтвердит прежний статус без нового номера.
При повреждении или неподдерживаемой схеме пакет не сбрасывает реплику и
не перезаписывает её свежей БД. SQLite может штатно создать служебные sidecar
при восстановлении WAL.

## Лимиты и проверка

| Объект | Предел |
| --- | --- |
| ID операции, автора, записи или родителя | 128 байт UTF-8 на ID |
| Родители | 32 на операцию |
| Операция | 64 КиБ в JSON, включая Base64 |
| Ожидание | 64 операции и 256 КиБ суммарного JSON |
| Принятая история | 4 096 операций и 8 МиБ суммарного JSON |
| Состояние целиком | 10 МиБ до шифрования |

При превышении лимита запись отклоняется, а подтверждённое состояние
остаётся доступным. Лимит количества ожидающих операций выражен статусом
`Rejected` и `syncmerge.ErrPendingLimit`. Прочие лимиты хранения дают
`ErrLimit`. История и tombstone сохраняются целиком. Лимиты относятся к
логическому состоянию. Размер SQLite, WAL и данные предыдущих поколений
на диске зависят от страниц и checkpoint. Долгое чтение может задержать
сокращение WAL. Полное чтение, воспроизведение и шифрование снимка при
записи дают цену, пропорциональную размеру истории и разрешаемых
зависимостей. Эти границы подходят для проверки 2A. До интеграции нужны
замеры на репрезентативных синтетических наборах.

Тесты `go test ./internal/replicastore` используют временные каталоги.
Они проверяют чтение после открытия, конфликт редактирования с удалением,
сохранение и разрешение ожидания, повторы, повреждение и лимиты. Отдельный
тестовый процесс завершается принудительно после SQL UPDATE перед commit и
после commit до подтверждения. Следующее открытие проверяет результат по
состоянию, истории, счётчику и outbox. Тесты сканируют созданные SQLite
файлы и sidecar после записи, изменения, удаления, checkpoint и остановки
процесса. Сканирование маркеров дополняет проверку пути данных от Go до
SQL. Испытание покрывает аварийное завершение процесса. Сбои диска и
физическое отключение питания требуют отдельной проверки.

Следующий этап 2B привяжет ключ реплики к разблокировке, добавит проверяемый
перенос на копии v2, отдельное переключение активного хранилища, план отката
и нативные проверки Windows. Формат обмена, подписи и доставка outbox
появятся на следующих этапах. [Дорожная карта](ROADMAP_3_0.md)
