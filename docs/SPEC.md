# PasswordSaver — SPEC

Срез: `main` `9b7c1a3` (25.11.2026). Выпущена Standard 2.5.0 для Windows x64; код 3.0 пока изолирован от приложения.

## Стек и границы

- Go 1.26.4, Wails 2.12, Svelte 3/Vite 3, WebView2; тесты Go, `-race`, frontend и Playwright, сборка EXE в GitHub Actions.
- Один локальный vault. Go управляет ключами, сессией, TOTP, файлами и CRUD; Wails связывает Go с интерфейсом. Для локальной работы учётная запись и сеть не нужны; HIBP вызывается только явно.
- `crypto/v2/` — независимый движок Standard; `crypto/` — совместимость v1. GOST Lab не входит в Standard.

## Рабочие файлы Windows

`%LOCALAPPDATA%\PasswordSaver\vaults\default\`:

| Файл | Назначение |
| --- | --- |
| `vault_data.v2.enc`, `.bak` | Активный контейнер v2 и зашифрованная штатная копия. |
| `vault_format.state` | JSON-селектор v1/v2 (`v1-only`, `v1-prepared`, `v2-active`); активный v2 не откатывается на v1 автоматически. |
| `vault_data.enc`, `.bak` | Старый v1 и его копия, если присутствуют; исходники сохраняются при явной миграции. |
| `storage.migration.json` | Квитанция подтверждённого переноса из прежнего каталога, если перенос был. |

Внешний экспорт v2 — точные байты зашифрованного контейнера. Повреждённые файлы и прежние снимки при восстановлении сохраняются в зашифрованных диагностических архивах.

## Криптография и форматы

- **v1 (чтение/миграция):** JSON `{ciphertext,salt,nonce}` (Base64) + 32 байта HMAC-SHA256 со встроенным ключом приложения. Payload: AES-256-GCM; ключ — Argon2id от мастер-пароля (t=3, m=128 МиБ, p=4, 32 байта). HMAC v1 не является секретом от обладателя программы.
- **v2:** канонический JSON `format=passwordsaver-v2`, `version=2|3`, `aead=aes-256-gcm`, `kdf`, `wrapNonce`, `wrappedDEK`, `nonce`, `ciphertext`; в ревизии 3 добавлено `recovery`. Бинарные поля — Base64; тег GCM включён в шифротекст.
- **Ключи v2:** случайный DEK 32 байта шифрует JSON vault (записи и настройки TOTP). Argon2id (v19; по умолчанию t=3, m=64 МиБ, p=4; соль 32 байта) выводит KEK 32 байта из мастер-пароля; KEK оборачивает DEK. Для обеих операций AES-256-GCM применяются отдельные случайные nonce по 12 байт, тег 16 байт и доменно разделённый AAD. Парсер ограничивает и строго проверяет размер, каноничность, версии и параметры KDF до его запуска.
- **Recovery v2 rev.3:** ключ 256 бит с префиксом `PSRK1-`, показывается один раз. HKDF-SHA256 с отдельной солью выводит KEK для второй AES-GCM-обёртки DEK; слот связан с payload через AAD. Сброс по ключу ставит новый мастер-пароль, ротирует DEK и погашает ключ. Старые экспортированные копии могут оставаться доступными прежнему ключу. TOTP — проверка приложения после расшифрования, не защита офлайн-копии.
- **Запись v2:** временный файл, `Sync`, проверенная `.bak`, атомарная замена основного файла; восстановление требует аутентификации и явного подтверждения. Смена известного пароля переоборачивает DEK без изменения payload; сброс и отзыв recovery key перешифровывают payload с новым DEK.
- **Прототип 3.0:** `internal/syncmerge` хранит причинные версии, конфликты и tombstone в памяти. `internal/replicastore` сохраняет историю, ожидание, счётчик и outbox одним зашифрованным BLOB в SQLite schema 1 (`application_id=0x50535253`, WAL, `synchronous=FULL`). Ключ 32 байта передаёт вызывающий код; HKDF-SHA256 с новой солью выводит ключ AES-256-GCM; AAD связывает ID реплики, версию схемы и поколение. Драйвер `github.com/ncruces/go-sqlite3` 0.38.0 без CGO. Рабочий vault и Wails к этому хранилищу ещё не подключены.

## Решения 3.0

MVP спроектирован для двух Windows-устройств одного владельца и одного vault: локальная работа по умолчанию, явное подключение, офлайн-изменения, конфликты без потери вариантов. Предлагается необязательное HTTPS-реле только шифротекстов; формат обмена, ключи устройств, отзыв и сервер ещё не реализованы. Несколько независимых vault, мобильный клиент и совместный доступ отложены.
