# Остаточные файлы после прерванной записи (PR #12, P1)

## Причина

Атомарная запись создаёт временный файл в каталоге назначения, синхронизирует
его и только затем публикует. Завершение процесса или потеря питания до замены
может оставить временный файл, потому что deferred cleanup не выполняется.
Прежний строгий allowlist AppData отвергал такой файл и блокировал исправный vault.

Теперь allowlist отдельно различает обычные контейнеры, допустимые по метаданным
остатки записи и небезопасные/неизвестные объекты. Принадлежность файла прежнему
процессу не доказывается: остатки всегда считаются недоверенными.

## Аудит служебных объектов

| Объект | Кто создаёт / назначение | Политика |
| --- | --- | --- |
| `.vault-write-<N>` | `writeFileAtomic`: v1 primary/backup, v2 primary/backup, обновления selector, подтверждённое recovery | Допустим только обычный ограниченный по размеру файл; не читать, не использовать, не удалять |
| `.vault-v2-stage-<N>` | `writeFileAtomicNoReplace`: создание v2/backup/selector, кандидат v1→v2, диагностический архив, запись staging при переносе расположения | Та же политика; незавершённый файл не является кандидатом/backup/selector |
| `vault_data.enc.corrupt-*`, `vault_data.v2.enc.corrupt-*` | v1/v2 recovery: диагностическая копия повреждённого primary; v2 сначала резервирует имя | Существующая политика обычного файла с пределом размера; не выбирается активным, не удаляется |
| `.default-migration-<N>` | `MkdirTemp` в **родительском** `vaults`: staging копирования расположения | Не является файлом внутри managed root. Не выбирается и не удаляется после перезапуска. Внутри `default` неизвестен и запрещён |
| `storage.migration.json` | Квитанция завершённого переноса расположения | Существующий отдельный строгий разбор и ограничение размера |

Других паттернов CreateTemp/MkdirTemp в production Go-коде на этом этапе нет.
Новые произвольные префиксы не разрешаются.

`N` — каноническое десятичное uint32 от 0 до 4294967295, без ведущих нулей
(кроме самого `0`). Именно такой суффикс создаёт текущий Go 1.26 `os.CreateTemp`.
Пустые суффиксы, расширения, знаки, Unicode-цифры, иной регистр и числа за пределом
uint32 отклоняются как неизвестный объект. При изменении генератора имён Go
политика должна быть пересмотрена с тестами; произвольный шаблон не принимается.

Дополнительно проверяются абсолютный путь, компоненты каталогов, `Lstat`, обычный
тип файла, отсутствие symlink/reparse point и размер от 0 до
`max(maxVaultFileSize, crypto/v2.MaxContainerSize)` (общие writer-функции обслуживают
оба формата). Нулевой размер допустим: процесс мог завершиться сразу после создания.
Файлы выше предела, каталоги, FIFO, ссылки, junction и другие специальные объекты
останавливают операции. Совпадения имени недостаточно.

Ни содержимое, ни заголовок, ни ключи временных файлов не читаются: допустимость
по метаданным нужна только для решения, можно ли игнорировать этот объект при
обычной работе. Даже полностью аутентифицируемый контейнер под таким именем не
продвигается в primary/backup. Расширение inventory и квитанции его не включает.

## Поведение и диагностика

| Состояние | Поведение |
| --- | --- |
| Штатные vault-файлы и допустимые остатки | Путь остаётся доступен; selector, мастер-пароль и TOTP проверяются прежними методами. Исправность primary не предполагается до аутентификации |
| Primary повреждён/отсутствует, есть backup и корректный активный v2 selector | Существующий двухэтапный recovery `.bak`; исходный повреждённый primary архивируется. Временные файлы не участвуют |
| Только остатки, включая случай с одним selector без primary/backup | `incomplete-write`, вход/запись/создание нового vault запрещены. Нужен ручной анализ сохранённой копии папки |
| Штатный v2 без selector либо повреждённый/неизвестный selector | Прежний fail-closed выбор; остатки не разрешают обход, автоматический откат на v1 или новую активацию |
| Неизвестный/небезопасный объект | `error` с категорией `unsafe-entry`; вход и запись запрещены, никаких удалений |

Не вводится новый Wails API: `GetStorageLocationStatus` дополнен только полями
`temporaryFiles` (количество) и `diagnostic` (категория). Новые поля не содержат
имён, дополнительных полных путей, ошибок ОС или данных файлов. Предупреждение
показывается на экране входа и в открытом приложении; создание доступно только
при состоянии `ready`. Категория предупреждения не означает, что backup проверена.

`OpenStorageFolder` позволяет открыть только фиксированный managed-каталог для
ручной диагностики, даже когда небезопасен один из его дочерних объектов.
Каждый компонент пути самого каталога проверяется; при symlink/reparse в этом
пути открытие запрещено. API не принимает путь из frontend, не создаёт папки и
не меняет ACL в диагностическом состоянии.

При ручном разборе сначала закрыть приложение и сохранить копию **всего** тестового
набора на отдельный носитель, сохранив имена. Не переименовывать временный файл в
основной контейнер, не удалять его и не подменять `.bak`. Если есть корректная
резервная копия и selector, использовать штатное подтверждаемое восстановление.
Иначе экспортировать копию для анализа. Автоматической очистки или отдельной
процедуры удаления в этом PR нет.

## Атомарность, гонки и ограничения

- Writer-функции, AEAD, Argon2id, контейнеры и порядок sync/замены не меняются.
  Новый allowlist не используется как разрешение на запись по временным путям.
- Исчезновение допустимого temporary между ReadDir и Lstat допустимо: его мог
  убрать живой writer. Другие ошибки/небезопасные типы приводят к отказу.
- После проверки временного пути нет open/chmod/remove/rename по этому пути.
  `ensureStorageScaffold` не применяет ACL/режим доступа к временным именам.
  Кэш признания файла допустимым не создаётся; каждый следующий scan проверяет
  его заново. Временный файл может изменяться в работающем writer, поэтому его
  размер не используется как свидетельство завершения записи.
- Непустой destination переноса остаётся запрещённым, даже если содержит только
  остатки. Создание v2 повторно проверяет их под существующими write locks.
- Если все контейнеры исчезают при открытой v1/v2-сессии и остаётся только residue,
  следующее сохранение закрывает сессию и отказывает в создании файла.
- No-replace запись может оставить второй hard link к опубликованному inode.
  Обычный файл с таким именем также не читается/не удаляется. Изменение того же
  inode процессом с правами пользователя не предотвращается этой политикой.
- Абсолютная защита от процесса того же пользователя, меняющего файловую систему
  между проверками, не заявляется. Гарантии аутентификации, проверки ревизии и
  снимков recovery сохраняются. Ограничения Windows directory fsync остаются.
- Остаток может относиться к ещё работающей записи, а не только к прошлому сбою.
  Предупреждение консервативно; оно не устанавливает происхождение/актуальность
  содержимого и не предлагает автоматически удалить его.

## Регрессионные проверки

`storage_residue_test.go` проверяет оба префикса, v1/v2 login/TOTP и повторное
сохранение с backup, повреждённый/отсутствующий primary с `.bak`, сохранность
selector/v1/residue, диагностический архив, запрет использования временного как
backup, неизвестный selector, состояние только residue, неправильные имена,
границы размера, symlink/необычный тип, отсутствие удаления/чтения, отказ в
переносе на непустой destination, безопасное открытие только fixed folder и
одновременную проверку расположения при записи.

Отдельный дочерний тестовый процесс вызывает `os.Exit` после file Sync до
rename/link, минуя defer. Родитель запускает новую App-сессию и проверяет
сохранность контейнеров и действительного остаточного имени от Go CreateTemp.
Это воспроизводит прерванный процесс; потеря питания/поведение дискового кэша
этим тестом не доказываются. Windows-тест проверяет junction с временным именем.
Frontend-тесты проверяют предупреждение и заблокированные состояния.

Реальный Windows GUI в облачной Linux-среде не запускался. Ручные сценарии:
[WINDOWS_STORAGE_MIGRATION_TEST_PLAN.md](WINDOWS_STORAGE_MIGRATION_TEST_PLAN.md).
