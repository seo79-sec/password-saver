# PasswordSaver 2.5 — локальная архитектура и план разработки

Статус: 2.5-A реализуется в ветке `feature/v2.5-storage-location-foundation`.
Изменения должны пройти review, CI и ручные испытания Windows до merge.

## Цель

PasswordSaver 2.5 — зрелый **local-first** менеджер паролей без обязательной
регистрации, собственного сервера или подключения к сети. Основной формат —
версионированный контейнер v2 с AES-256-GCM, Argon2id, DEK/KEK.
Отдельная учебная GOST Lab остаётся отдельной редакцией, без автоматического
чтения/записи Standard-контейнеров.

## Этапы

### 2.5-A: хранение вне исполняемого файла

- По умолчанию в Windows использовать
  `%LOCALAPPDATA%\PasswordSaver\vaults\default\`.
- `password-saver.exe` и сопровождающая его контрольная сумма остаются
  в папке программы; пользовательские зашифрованные файлы хранятся отдельно.
- Реализовать централизованный **абсолютный** путь во всех backend API,
  включая login, CRUD, TOTP, backup/recovery, selector, migration, logout
  и reset. Не менять process-wide current working directory с помощью
  `os.Chdir` — это не надёжная граница между потоками, путями и сессиями.
- Ранее созданные vault-файлы рядом с `.exe` **не переносить автоматически**.
  При обнаружении старого каталога предложить явный перенос с подтверждением,
  проверкой AEAD/backup, атомарными копиями и сохранением исходных файлов.
- При наличии разных vault в исходном и целевом каталогах **остановиться**,
  не выбирать «первый найденный», не затирать файлы и показать пользователю
  понятное решение конфликта.
- Защищать пути от неожиданных символьных ссылок, неправильных разрешений,
  смены файлов при копировании и нарушения атомарности. Windows ACL должны
  ограничивать доступ в пределах поддерживаемых прав пользователя.
- Создать экран расположения данных с кнопкой «Открыть папку».
- Ручные тесты на Windows с новым и существующим **синтетическим** vault.
- Не менять формат криптоконтейнера.

- Реализована централизованная маршрутизация backend-операций в AppData,
  явное двухшаговое копирование старых зашифрованных файлов и экран статуса.
- Миграция аутентифицирует активный контейнер (или проверенную резервную
  копию, если активный файл повреждён), затем копирует точный зашифрованный
  снимок во временный каталог, проверяет побайтовое равенство и публикует
  каталог атомарным перемещением. Исходные файлы не меняются и не удаляются.
- До успешной Windows CI и ручной проверки этап не считается готовым к релизу.

### 2.5-B: несколько независимых локальных хранилищ

- Список хранилищ (ID без персональных данных), создать/переименовать/
  переключить/архивировать, отдельная DEK/KEK-сессия и политика TOTP.
- Проверка отсутствия cross-vault записей и утечек секретов между сессиями.
- Без общего «глобального мастер-пароля» по умолчанию.
- Никакого автоматического слияния хранилищ.

### 2.5-C: резервное копирование и импорт/экспорт

- Ручной экспорт зашифрованного контейнера в выбранный путь.
- Управление локальными резервными копиями и проверка целостности.
- Понятный сценарий восстановления с проверкой ключа и версии.
- Импорт с валидацией схемы, обнаружением дубликатов и предпросмотром,
  без безусловной замены текущего vault.

### 2.5-D: расширенное локальное восстановление и удобство

- Отдельное проектирование recovery key и разделения секретов по Шамиру:
  восстановление должно опираться на специальный wrapped-DEK механизм,
  а не на восстановление мастер-пароля из небезопасного текста.
- Windows Hello / аппаратный ключ — только после выбора поддерживаемого
  и проверенного API и угрозомодели; не считать биометрию самостоятельным
  эквивалентом мастер-ключа.
- Зашифрованные вложения, история изменений и UI-улучшения — отдельные PR,
  с лимитами размеров, тестами и оценкой рисков.

## Ограничения и приёмка

- Каждый этап — отдельный PR, Go/frontend тесты, race detector, Windows CI,
  ручные сценарии и review до merge.
- Данные старого каталога и v1-файлы нельзя удалять при установке/обновлении.
- Релиз v2.0.0 и его SHA-256 не изменять; v2.5 — следующая ветка разработки.
- Не внедрять сервер, VPS, облачную синхронизацию и коллективный доступ
  до отдельной архитектуры PasswordSaver 3.0.
- Функция считается готовой только после интеграции и проверки на Windows.
