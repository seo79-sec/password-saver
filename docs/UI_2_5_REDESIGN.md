# PasswordSaver 2.5: Minimalist Desktop UI

Ветка `feature/v2.5-ui-redesign` создана от `main` после объединения PR #12.
Основа — настольная часть предоставленного макета. Презентационная рамка окна,
телефон и декоративный фон за окном в приложение не включены.

## Компоненты и состояние

`App.svelte` остаётся владельцем авторизации, расшифрованных записей, полей
мастер-пароля/редактора/TOTP, токенов миграции и challenge-операций.
Представление разделено на:

- `AppShell`, `Sidebar`, `LoginView` — оболочка и реальная навигация;
- `SearchAndFilters`, `PasswordList`, `PasswordRow`, `PasswordEditor` — работа с записями;
- `SecurityCenter`, `SecurityView`, `StorageView`, `StorageStatusBar`, `StorageDiagnostics`;
- `SettingsView`, `ThemeSelector`, общий `Modal`, локальный набор SVG `Icon`.

Общие стили находятся в `frontend/src/style.css`, токены светлой и тёмной схемы —
в `frontend/src/styles/tokens.css`, логика тем/категорий/локальных счётчиков — в
`frontend/src/ui.js`. Внешние иконки, favicon-сервисы, аналитика и веб-шрифты не нужны.

Реальные категории — «Общие», «Работа», «Соцсети», «Игры», «Финансы». Их нельзя
превратить в «Сайты/Приложения» только по названию без потери смысла старых данных.
Существующая запись категории в `title` через `|||` сохранена. Неизвестные старые
категории тоже отображаются и доступны для фильтра/редактирования.

## Темы

Новые установки используют Light. Существующие `localStorage.theme=light/dark`
сохранены. System использует `prefers-color-scheme` и его событие `change` без
перезапуска. Сохраняется только предпочтение, а не вычисленный системный цвет.
Выбор применяется до paint внешним parser-blocking head script из единого
theme runtime; App повторно использует тот же controller. Подписка удаляется
при уничтожении компонента. Недоступный theme storage не
мешает применить схему в текущем запуске.

Светлая схема близка к макету. Тёмная использует отдельные графитово-синие
поверхности. Для обычного текста и белых подписей кнопок цвета немного углублены
относительно исходных ориентиров, чтобы сохранить контраст. Системный `prefers-reduced-motion`
отключает CSS-анимации. На границах авторизации нет отложенного удаления старого DOM.

## Подключение к backend и безопасность

Используются прежние generated Wails bindings: Login/LoginV2/Verify2FA, CRUD,
создание v2, GetVaultStatus/GetStorageLocationStatus, TOTP setup, idle/clipboard,
AppData selection/prepare/confirm/cancel, v1→v2 activation/cancellation, reset и
v1/v2 recovery. Go API и исходники backend не изменялись.

TOTP в боковой карточке определяется ответом реального входа/восстановления и
успешным ConfirmAndEnable2FA. Backup показывает только наличие; время создания
и криптографическая исправность не выдумываются. «Основное» — единственный
текущий стандартный vault, а не система нескольких хранилищ.

На вкладке «Безопасность» сохранены показатели слабых, повторяющихся, старых
и найденных в HIBP паролей. По нажатию на локальный показатель открываются
соответствующие записи. Повторы считаются через Map, включая пароли вроде
`__proto__`. Эвристика слабости соответствует прежнему UI и не гарантирует стойкость.

HIBP запускается только после отдельного согласия. На сервер уходит SHA-1 prefix,
открытые пароли не отправляются. Состояния: не проверено, выполняется, завершено,
частичный результат, ошибка. При полной ошибке показывается «—», а не ноль утечек.
При блокировке/unmount AbortController отменяется, поколения запрещают старые
результаты. Изменение записей сбрасывает результат и отменяет предыдущую проверку.

Маскирование действует по умолчанию в таблице и каждом вновь открытом редакторе.
Копирование не требует показа. Backend timeout, проверка по возвращении фокуса,
безопасная очистка clipboard и защита от устаревших GetAccounts сохранены.
Выход/автоблокировка закрывают модальные окна, сбрасывают пароль/редактор/TOTP,
настройку 2FA и challenge-токены. Поздние ответы входа, TOTP setup и миграции
проверяют поколение. Очистка всех копий JavaScript-памяти не гарантируется.

Общий Modal управляет фокусом, Tab/Shift+Tab, Escape и возвратом фокуса;
background становится inert. Подготовку AppData можно закрыть во время ожидания:
поздний токен отменяется. Подтверждённая запись не прерывается кнопкой закрытия.

Предупреждение о служебных остатках теперь говорит, что их наличие не подтверждает
целостность vault. Оно не утверждает «Основное хранилище не изменено».
Диагностические блокировки, конфликты, неизвестный selector и подтверждаемое
восстановление остаются под контролем прежнего Go backend.

## Автоматические проверки и скриншоты

```sh
cd frontend
npm ci
npm test
npm run build
npx playwright install --with-deps chromium
npm run test:ui
# Linux с уже установленным Chromium:
CHROMIUM_PATH=/usr/bin/chromium CAPTURE_UI=1 npm run test:ui
```

Browser suite запускает **настоящий Svelte UI**, а Wails boundary заменяет только
тестовым bridge из `frontend/e2e/bridge.js`. Никакой demo-режим/обход авторизации
в production не добавлен. Все записи и токены синтетические. Это проверка UI и
вызовов Go bindings, а не доказательство выполнения Go через WebView2.
Go интеграционные тесты и Windows Wails build проверяются отдельно.

## Ручная проверка Windows перед одобрением

Windows GUI в облачной Linux-среде не запускался. На изолированном профиле с
синтетическими данными нужно проверить:

1. Запуск Windows EXE/WebView2 в пяти размерах, DPI 100/125/150/200%, Segoe UI,
   системные темы Windows и их изменение без перезапуска.
2. Настоящие CRUD, маскирование/показ/clipboard, search/categories, модальные
   окна с Tab/Shift+Tab/Escape и focus restore.
3. Вход v1/v2, неверный пароль/код TOTP, повторный вход, idle timeout при
   открытом редакторе и настройке TOTP, сон/возврат фокуса.
4. Native directory picker, AppData migration, отмена/истечение challenge,
   конфликт, временные файлы, подтверждение v1→v2 и отмена подготовки.
5. Восстановление повреждённого/отсутствующего primary из backup с сохранением
   архива, селектора и TOTP; reset только синтетического v1 с отдельным challenge.
6. Реальный Windows clipboard (15/30/60 сек): новое скопированное содержимое
   пользователя не удаляется. HIBP — только после согласия; offline/errors/lock.

Подключение устройств, Android, pairing/QR и USB-ключи оставлены для 3.0.
Криптография, файловые форматы, релизные метаданные, пользовательские vault и
алгоритмы AES/Argon2id не изменялись. Merge и публикация релиза не выполняются.
