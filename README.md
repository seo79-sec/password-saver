**PasswordSaver Standard 2.5.0** — локальный настольный менеджер паролей на Go, Svelte и Wails. Новые установки сразу создают AES-256-GCM/Argon2id-хранилище v2 с зашифрованной резервной копией; старые файлы v1 `vault_data.enc` поддерживаются только для совместимости и миграции. Это единственная сборка текущего этапа; экспериментальная редакция GOST Lab пока не входит в приложение. Архитектура описана в [docs/EDITIONS.md](docs/EDITIONS.md).

## Возможности

- Локальное зашифрованное хранилище с зашифрованной резервной копией `.bak` и явным подтверждением восстановления.
- Экспорт зашифрованных копий v2, проверка без записи, полное восстановление и выборочный импорт. [Операции с копиями](docs/V2_EXTERNAL_BACKUP.md)
- Смена мастер-пароля v2 и восстановление доступа по заранее сохранённому ключу. [Ключ восстановления](docs/V2_RECOVERY_KEY.md)
- Необязательная двухфакторная аутентификация TOTP.
- Генератор паролей, категории, поиск и индикаторы состояния паролей.
- Сохранённые пароли скрыты по умолчанию; их можно копировать, не показывая.
- Настраиваемая автоблокировка через 1, 5, 10 или 15 минут и очистка clipboard через 15, 30 или 60 секунд.
- Необязательная проверка Have I Been Pwned (HIBP). Приложение вычисляет SHA-1 локально и отправляет HIBP только первые пять шестнадцатеричных символов хеша; открытый пароль не передаётся.
- Названия сервисов не отправляются стороннему favicon-сервису.

## Хранилище и приватность

Новый каталог сразу использует v2: `vault_data.v2.enc`, `vault_data.v2.enc.bak` и `vault_format.state`. Старый формат v1 использует `vault_data.enc` и `vault_data.enc.bak`. При явной миграции существующего v1 на v2 исходные файлы сохраняются. В Windows рабочие файлы хранятся в `%LOCALAPPDATA%\PasswordSaver\vaults\default`. Перенос из прежнего каталога требует явного подтверждения и сохраняет исходные файлы. Восстановление обеих версий требует проверки резервной копии и явного подтверждения; повреждённый основной файл v2 архивируется рядом для диагностики. Восстановление возвращает состояние на момент копии и может потерять более поздние изменения. Активный v2 никогда автоматически не переключается на v1.

Проверка HIBP выполняется только по явному действию пользователя и требует сети. Для тестирования используйте синтетические пароли. Открытые пароли HIBP не отправляются.

При блокировке интерфейс освобождает ссылки на чувствительные значения, но JavaScript и операционная система не гарантируют стирание каждой копии из памяти. Очистка clipboard выполняется best effort и зависит от доступа к системному буферу обмена.

## Требования для сборки

- Go **1.26.4 или новее**, согласно `go.mod`.
- Node.js **24** и npm (используйте npm из комплекта Node.js; CI устанавливает зависимости через `npm ci`).
- Wails CLI **v2.12.0**.
- Для сборки Windows-приложения из исходников: Windows 10/11, поддерживаемый Wails компилятор MinGW-w64 и инструменты WebView2. См. [инструкцию по установке Wails для Windows](https://wails.io/docs/gettingstarted/installation).
- Для запуска готового Windows-приложения требуется Microsoft Edge WebView2 Runtime.

## Сборка и тесты

```sh
cd frontend
npm ci
npm test
npm run build
cd ..

go test ./...
go test -race ./...
go vet ./...
go build ./...

go install github.com/wailsapp/wails/v2/cmd/wails@v2.12.0
wails doctor
wails build -platform windows/amd64 -clean
```

Исполняемый файл появится в `build/bin/password-saver.exe`. Поддерживаемый релизный артефакт Standard — Windows x64. Подготовка кандидата для релиза и ручной план проверки Windows описаны в [инструкции выпуска](docs/RELEASING.md) и [плане ручного тестирования](docs/WINDOWS_MANUAL_TEST.md). Релиз не публикуется автоматически.

## Установка

Скачайте опубликованный Windows x64 Standard ZIP со страницы GitHub Releases и проверьте его SHA-256. Распакуйте архив и запустите `password-saver.exe`. Кандидаты 2.5.0 доступны отдельно в [GitHub Actions](https://github.com/seo79-sec/password-saver/actions) по [инструкции выпуска](docs/RELEASING.md). Требуется WebView2 Runtime. Перед перемещением или заменой файлов приложения сохраните вместе активное хранилище, его `.bak` и `vault_format.state`. Не используйте настоящее хранилище при ручных или разрушающих проверках.
